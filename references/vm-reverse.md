# dword 脚本 VM 逆向方法论

2000 年代日式视觉小说的自研脚本引擎，绝大多数是同一个形状：
**一个 uint32 数组，`[opcode][操作数类型][操作数值]...`，由一个 C 写的 switch 分发器解释执行。**

掌握这一套，KAAS / Adv32 / 各家自研 VM 都能通。

---

## 第 1 步：判断是不是这种 VM

**判据**

- 数据文件头部有一个 dword 等于「代码区 dword 数」，且 `code_len * 4` 之后紧跟着看起来像文本的东西
- 文件里存在大量「递增的 dword 序列」（跳转标签表）
- exe 里有一个巨大的 `switch`，跳转表项数在 32–128 之间

**本项目（KAAS / ww4r.id）的头部**

```
dword[0] = 67393       代码区 dword 数（0x41D04 / 4）
dword[1] = 297549      标签表偏移（* 4 = 0x122934）
dword[2] = 15          未知
dword[3] = 200         未知
dword[4..67392]        VM 指令流
0x41D04 .. 0x122930    文本区（14714 页，SJIS，lead ^ 1）
0x122934 .. EOF        标签表（2539 个严格递增的代码偏移）
```

**注意**：`dword[2]` 不要当成标签数量。本项目 `dword[2]=15`，实际标签有 2539 个
（`(filesize - label_offset) / 4`）。`vm.json` 里 `label_count_word: null` 表示「算到文件尾」。

---

## 第 2 步：找 ip 变量（最关键的一步）

**这是整件事的枢纽。** 找到「指令指针存在哪个全局变量」，后面全部好办。

**特征签名**：分发器在每条指令执行完后，一定会把新 ip 写回全局：

```asm
add  edx, 3                  ; edx = 下一条指令偏移
mov  dword ptr [0x897d70], edx
```

**找法**

1. 在 exe 里找 switch 分发器：搜「大跳转表 + 多次 `cmp` 边界检查」
2. 看每个 case 的尾部，找 `mov [imm32], <reg>` 且 `<reg>` 刚被 `add`
3. 那个 `imm32` 就是 ip 变量地址

**本项目**：`ip = [0x897d70]`，主分发器 `FUN_0042bae0`，跳转表 `0x42d92c`（64 项，合法 op 2–0x41），
公共尾 `0x42bb68`（`add edx,5`），回分发 `0x42baff` / `0x42baf5`。

---

## 第 3 步：读 opcode 长度表

**这是最可靠的做法**：每个 case 尾部的 `add edx, N` 里的 `N` 就是该指令长度。不需要猜。

```python
# 伪代码
for case_addr in jump_table:
    for insn in disasm(case_addr, until_next_case):
        if insn.mnemonic == 'add' and insn.operands[0] == 'edx':
            length[opcode] = imm(insn)   # 注意：立即数可能是十进制
```

**踩过的坑**

- capstone 输出 `edx, 3` 是十进制没有 `0x`，正则 `^0x[0-9a-f]+$` 匹配不到 → 用 `int(v, 0)`
- 写回指令是 `mov dword ptr [0x897d70], edx`，判等要写成
  `IP in op_str and op_str.endswith(', edx')`，不要 `op_str == '[0x897d70]'`

**变长指令**：长度不在 case 里写死，而是由操作数个数算出来：

| opcode | 长度公式 | 含义 |
|---|---|---|
| `0x27` | `A[ip+2] * 2 + 3` | `NOT IN [n][v0][v1]...` 跳到 T |
| `0x28` | `A[ip+1] * 2 + 2` | `PUSH` 变参 |
| `0x40` | `A[ip+1] * 5 + 3` | 复合条件 |

`vm.json` 里用 `$N` 表示 `A[ip+N]`，例如 `"len": "$2*2+3"`。

---

## 第 4 步：确定操作数编码

**本项目**

```
A[ip+0] = opcode
A[ip+1] = 操作数0 的类型    0=立即数  1=变量  2=二级间接
A[ip+2] = 操作数0 的值
A[ip+3] = 操作数1 的类型
A[ip+4] = 操作数1 的值
```

即：

```
read_operand(k):
    if A[k] == 0: return A[k+1]              # 立即数
    if A[k] == 1: return vars[A[k+1]]        # 变量
    if A[k] == 2: return vars[vars[A[k+1]]]  # 二级间接
```

**为什么要区分**：`v[v39]` 这种二级间接是「数组访问」，剧情数据常用它。
看到 `op1B v900 v[v39]` 就读作「`v900 = 数组[v39]`」。

---

## 第 5 步：确定比较运算符的极性（必做）

**不要猜。** 运算符索引和直觉经常不一致，读反会让所有条件结论颠倒。

**本项目反汇编 `op18` handler（`0x42c0ab`）+ 运算符表 `0x42da2c` 得到的真实映射**：

```
索引 0 -> <      索引 1 -> <=     索引 2 -> >
索引 3 -> >=     索引 4 -> ==     索引 5 -> !=
```

之前一直用 `['>=', '>', '<=', '<', '!=', '==']`，把 0↔3、4↔5 全反了，
导致「`IF v100 == 1` 才播」实际是「`IF v100 != 1` 才跳过」。

**验证方法**：写一段已知行为的测试代码（例如 `if 1 < 2 then` 明显成立），
在调试器里跑一遍看走哪个分支。或者直接读 handler 里的 `setcc` / `cmov` 指令。

---

## 第 6 步：复合条件的语义

`op 0x40` 是 `[40][n][L0][op0][R0][L1][op1][R1]...[target]`。

**本项目反汇编（`0x42c18f`）确认**：ebp 计的是「**不成立**的项数」，
最后 `cmp ebp, edi; jne target` —— 即：

```
if ANY(cond_i 成立) then goto target
```

等价于「**全部成立才继续往下走**」。所以显示成：

```
SKIP-IF v606 != 9 | v531 < 450 | v532 < 450 -> 16121
```

读作「v606 不等于 9，或爱动摇度 < 450，或圣华动摇度 < 450，就跳到 16121」，
也就是「三者**全部**满足才播放」。

---

## 第 7 步：建立全量指令表

**种子 + CFG 遍历**

```python
seeds = [entry] + labels                      # 入口 + 标签表
for each seed:
    while 位置未访问:
        len = 长度表[opcode]
        if len is None: 断流
        记录 (ip, len)
        for t in 跳转目标: 加入队列
        if opcode 是停止指令(JMP/RET): 断流
        ip += len
```

**判据**：覆盖率（按区间合并算，不要用长度求和——会因重叠虚高）。
本项目 18998 条指令 / 90.5% 覆盖，2539 个标签，2518 个文本块全部对齐。

**遇到覆盖率卡住**

用 `scripts/oplen.py`：**覆盖率最大化反解**。

原理：长度猜错几乎必然在几步内落到操作数中间，产生非法 opcode。
所以「解码出最多 dword 的长度表」在实践中就是正确的那张表。坐标上升逐 opcode 求解，2–4 轮收敛。

**注意**：能读汇编就直接读，别用这个方法——反解出来的值偶尔会因为「碰巧多解几条」而偏大。
只在 exe 被加壳/剥离时用。

## 第 8 步：函数切分

```
STARTS = {entry} ∪ 标签表 ∪ 所有 JMP / 条件跳转 / CALL 的目标
BODY[s] = 从 s 顺序解码直到停止指令（或断流）
OWN[p] = 覆盖 p 的「最小起点函数」
```

**为什么用线性解码而不是完整 CFG**：条件块的尾部是靠 fallthrough 到达的，
线性解码已经覆盖；而完整 CFG 遍历在几千个函数上会慢两个数量级
（本项目：2.9 秒 vs 70 秒）。

**必须加 limit**：`vm.linear(s, limit=s+4000)`。否则没有停止指令的函数会一路解码到 `code_len`。

---

## 第 9 步：守卫传播（攻略的核心）

**问题**：一个文本块自己不带条件。它的可见性由两层决定：

1. **局部守卫**：跳过了它的前向条件跳转
2. **继承守卫**：调用链上层跳过了这个 CALL 的条件

**算法**

```python
COND = {q: cond_at(q) for q in ins if 是前向条件跳转}

def guards_at(p):
    """区间 [q, q+len) 包含 p 的所有前向跳转"""
    return [c for c in FWD if c.q < p < c.t]

# 不动点：把 caller 的守卫传给 callee
for round in range(12):
    for callee, sites in CALLS.items():
        for q in sites:
            guard[callee] |= guards_at(q) | guard[OWN[q]]
    if 没变化: break

# 最终：文本块的守卫 = 所属函数守卫 ∪ 块自己的前向守卫
```

**本项目结果**：2518 个文本块，1486 个带守卫；守卫变量分布
`v100 (253) > v69 (44) > v900 (33) > v138 (24)`。

`v100` 一家独大是个强信号：它控制「同一场景的 4 个版本」（视角/对象不同），
253 个块受它控制。这种「单个变量压倒性占比」通常意味着视角分支或角色选择。

---

## 第 10 步：从守卫到攻略

**组织方式**

1. 按函数分组（一个函数 = 一个事件/场景）
2. 提取函数内的阈值序列（`if v531 >= 400 then v900 = 1` 这种模式）
3. 按变量分组 → 每个变量 = 一个角色的进度
4. 跨变量引用（`--xref`）→ 角色联动关系

**本项目的关键发现**：圣华的代码在 `16090` / `16173` 读了 `v531`（**爱**的动摇度）：

```
SKIP-IF v606 != 9 | v531 < 450 | v532 < 450 -> 16121
```

这就是「只练圣华剧情不出来」的根因——联名事件要求两个人的数值同时达标。

**方法论要点**

- **先读游戏自己给的提示文本**。脚本里的提示语/教程/旁白往往直接说明了机制。
  反汇编 3000 行调度器之前，先用 `--texts` 搜关键词。
- **用说话人归属判断变量归属**。变量编号相邻、代码顺序相近时靠猜容易错。
  统计每个变量控制范围内「独占文本块」的说话人，谁多就是谁。
  本项目靠这个纠正了「紫」和「樱」的互换。
- **进度计数器比数值门槛更硬**。用户报「数值够了但不出剧情」时，
  先找章节/天数计数器（本项目 `v606`，0–16），而不是继续调数值。

## 常见陷阱

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 运算符极性读反 | 所有条件结论颠倒 | 反汇编 handler 确认一次 |
| `op1B` 当成赋值 | 数据流全错 | 它可能是「压入值+返回地址」的块入口 |
| `0x25` 当成长度 2 | 解码错位 | 它可能是 RET，长度 1 |
| 线性解码不加 limit | 跑几十分钟 | 加 `limit=s+4000` |
| 覆盖率用长度求和 | 显示 >100% | 用区间合并 |
| 标签数取 `dword[2]` | 只解出 15 个函数 | 算到文件尾 |
| 完整 CFG 遍历所有函数 | 慢 20 倍 | 用线性解码 |
| 长度表达式每次跑正则 | 慢 25 倍 | 预编译成 code object |

## 工具速查

```bash
--list LO HI      反汇编区间
--funcs           列函数入口
--callers N       查调用者
--xref N          查变量引用（找剧情耦合最快）
--body N          打印函数体
--texts           列所有文本块
--dump FILE       导出指令表
```

`--xref` 是最有价值的一个：想确认「A 角色的代码有没有读 B 角色的变量」，
一条命令就出来。
