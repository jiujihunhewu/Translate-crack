# 案例：KAAS 引擎（DISCOVERY / 2004）

一个完整的实战记录。用作参照——遇到同引擎或同形状的 VM 时，直接套这里的参数。

---

## 引擎识别

- 厂商 DISCOVERY，2004 年，DirectX 8，800×600
- 引擎名 **KAAS**（作者 karry / TKCOB），版本串 `KAAS12` / `4R Edition build 35`
- 数据文件 `*.id`，可执行 `*.exe`（未加壳，PE32，ImageBase `0x400000`）
- 段布局：`.text 0x401000` / `.rdata 0x442000` / `.data 0x444000` / `.rsrc 0xcc4000`

**同类引擎特征**：`id` 后缀的数据文件 + 单 exe + 文本走 GDI `TextOutA`。
遇到 `*.id` 先按本文档的参数试。

---

## 文件结构（`game.id`）

```
dword[0]   = 67393        代码区 dword 数
dword[1]   = 297549       标签表偏移（* 4 = 0x122934）
dword[2]   = 15           未知（不是标签数！）
dword[3]   = 200          未知
dword[4..67392]           VM 指令流
0x41D04 .. 0x122930       文本区，14714 页
0x122934 .. EOF           标签表，2539 个严格递增偏移（min 2042, max 67032）
```

文件总大小 1,200,352 字节。

**文本区起点指纹**：`0x41D04` 处是 `82 49 80 5b`（首行菜单文字的存储形式）。
把它写进配置注释，每次构建前校验，防止误用已打补丁的文件。

**文本寻址**：`op41` 的 `X` 是文本索引，字节偏移 = `0x41D04 + X * 2`。

**`0x35` 的分支**：`cmp eax,0x3e7`（999）、`0x384`（900）是特殊返回值，
其余走 `[eax*4+0x444210]` 的 CG 表。

**运算符表**（`0x42da2c`，6 项）：`0=< 1=<= 2=> 3=>= 4=== 5=!=`

## 文本层

**存储格式**

- 双字节字符，lead 翻转 bit0（`lead ^ 1`）
- `00 00` → 页内换行
- gap 含 `03 00 02 00` → 翻页（主）
- gap 含 `01 00 02 00` → 翻页（次）
- 句首 `01 5e d1 b2` 是说话人控制码，提取后需清理（正则 `^[\x00\^\uff61-\uff9f\u70d9]+`）

**规模**：22143 条文本串 / 394023 字符 / 788046 字节 / 14714 页

**每行宽度**：原版硬切在 25 个全角字（50 字节），长句拆成多行同屏显示。
译文要按日文同样的断点分行，否则会超出文本框。

---

## 汉化链路

```
逻辑字节流（GBK）
  → 每字符首字节 ^ 1（预翻转）
  → 写入文件
  → 引擎加载时再 ^ 1
  → 交给 TextOutA，按字体字符集（改成 GB2312）解码
```

**四个必须处理的点**

1. pad 用 `A0 A1`（全角空格），绝不用 `00` —— `00` 是换行控制码
2. ASCII 全角化（引擎按偶数位置翻转 bit0，半角会打乱对齐）
3. 长度强制偶数
4. 超预算回退原文并报告

**字体 patch**：`LOGFONTA.lfCharSet`（偏移 23）从 `0x80`（SHIFTJIS）改成 `0x86`（GB2312），
`lfFaceName` 改成 `SimSun`。改完后 315,392 → 315,904 字节（字符串变长导致）。

**最终结果**

```
translated 22143 / kept 0 / over 0 / odd 0
verify: total 22143, missing 0, mismatch 0
冒烟测试：620 次点击 / 464 次推进 / 0 崩溃
补丁包 1,025,672 字节
```

**改不了的**：标题菜单、CG 画廊、音楽モード、`Machine-999` 之类的界面文字是英文位图，
不在文本层。补丁覆盖不到，必须如实说明。

## 攻略层的结论

### 数据结构

- **5 位女主**，各有一个动摇度变量和一个事件号变量
- **动摇度增长公式**（`1737–1937`）：

```
v935  = 训练项目残差（0..7）
v935 %= 8
v935 -= v611..v615          ; 固定步长累加器
if v935 > 999: v935 += 999
v531  += v935               ; 加到对应角色的动摇度
```

即 `动摇度 = 训练残差 + 点部位加成`，训练和点部位加的是同一个累加器。

### 训练九级阈值

`36 / 81 / 144 / 225 / 324 / 441 / 576 / 729 / 900` = `6² … 30²`，
四项同时达标才升级（`op 0x40` 复合 AND，`3262–3486`）。

### 分叉变量只有三个

| 变量 | 取值 | 含义 | 影响块数 |
|---|---|---|---|
| `v100` | 1–4 | 同一场景的 4 个版本（视角/对象） | 253 |
| `v900` | — | 当前事件号 | 33 |
| `v69` | 0/2 | 跳过片头 / 播片头 | 44 |

`v100` 在脚本里**从未被写入**，由引擎设置。

### 角色联动（最容易踩的坑）

爱和圣华共用**同一个剧情进度计数器 `v606`（0–16）**：

- `v606 < 8` → 联合篇，门槛取 `max(爱动摇度, 圣华动摇度)`
- `v606 >= 8` → 各自个人线开放

联合篇有 8 章，其中两章**锁定在指定女主**：

```
第5章  SKIP-IF v100 != 2 | v44 != 1   → 必须找「爱」
第8章  SKIP-IF v100 != 1 | v44 != 2   → 必须找「圣华」
```

`v44` = 今天找的是哪位女主（1 爱 / 2 圣华 / 3 千绘 / 4 樱 / 5 紫）。

**后果**：只练圣华时 `v44` 恒为 2，第 5 章永远刷不出，进度卡在 `v606=4`，
到不了 8，圣华个人线一场都不开。**动摇度涨到 900 也没用，门槛在剧情进度上。**

**联名事件**（第 10 章，函数 `8315`，被 `12527` / `16275` 调用）：

```
v606 == 9 且 爱动摇度 >= 450 且 圣华动摇度 >= 450
```

三个条件缺一不可。

### 点身体部位系统

`v107 = 1..5` 选部位，每轮对话点一次，给该角色 **+1 / +3 / +5** 动摇度，
**无上限**（全脚本搜不到对 `v611–v615` 的比较指令，只有加法）。

| `v107` | 部位 |
|---|---|
| 1 | 腿 |
| 2 | 眼睛 |
| 3 | 手臂 |
| 4 | 臀部（仅后期轮次，7–10 条台词，**推测**） |
| 5 | 胸 |

轮次：爱 33 轮 / 其余 36 轮。全点最优的累计加成：爱 165、圣华 178、千绘 180、樱 176、紫 174。

### 角色变量归属（踩过坑）

`v604` 和 `v605` 一开始搞反了。判据是**独占文本块的说话人统计**：

- `v604` 组：さくら 13 句 / 紫 0 句 → `v604 = 樱`
- `v605` 组：紫 11 句 / さくら 0 句 → `v605 = 紫`

这个判据比「代码顺序 + 剧情猜测」可靠得多，遇到多角色共用结构时优先用。

## 时间线：这个项目踩过的所有坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 每屏只显示第一行 | pad 用 `0x00`（换行控制码） | 改 `A0 A1` |
| 提取出 47889 条碎句 | lead 范围漏了 `0x80` | 放宽到 `0x80-0x9F, 0xE0-0xFD` |
| 译文命中率 45% | 行首偏移只在首次置值 | 修 `pages.py` |
| 把 `fopen/fread/fclose` 当成解码器 | 函数识别错 | 交叉验证调用点 |
| 自动标定过拟合（op06→10、op40→13） | 坐标下降陷入局部最优 | 改读 case 块控制流 |
| 覆盖率只有 13.5% | 入口点不全 | 种子加标签表 + 跳转目标 |
| 樱的事件解出 0 个 | `NOTIN` 的值读错位置（`+4+2i` 应为 `+3+2i+1`） | 修读取偏移 |
| 所有条件结论颠倒 | 运算符表读反（0↔3、4↔5） | 反汇编 handler 确认 |
| `op40` 语义理解错 | 以为「全部成立」，实际「任一成立即跳」 | 反汇编 `0x42c18f` |
| 紫和樱的事件表互换 | 靠代码顺序猜 | 用说话人归属判定 |
| 守卫传播 70 秒 | 完整 CFG 遍历 + 每次跑正则 | 线性解码 + 预编译 |
| 标签只解出 15 个 | 用了 `dword[2]` 当数量 | 算到文件尾 |
